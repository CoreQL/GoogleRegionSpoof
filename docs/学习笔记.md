# 学习笔记：Nrfr 与 GlobalKit（com.tiktok.unlocker）

记录于 2026-11-21，研究对象为两个 GitHub 仓库的公开内容（README、源码/元数据、更新日志、第三方声明）。

## 1. Ackites/Nrfr —— 系统层覆写，不用 Xposed

**它是什么**：免 Root 的 SIM 卡国家码修改工具。由两部分组成：

- Android 应用（Kotlin + Jetpack Compose）：选 SIM 卡、选目标国家码、应用/还原；
- 桌面端快速启动工具（Go + Wails + React）：自动检测设备、装 Shizuku、装应用。

**核心手段（与 Xposed 完全不同）**：

- 借助 **Shizuku** 拿到特权 Binder，把系统服务 `ICarrierConfigLoader` 包一层
  （`ShizukuBinderWrapper(TelephonyFrameworkInitializer…carrierConfigServiceRegisterer.get())`）；
- 调 `ICarrierConfigLoader.overrideConfig(subId, PersistableBundle, true)` 覆写运营商配置，
  关键键：
  - `CarrierConfigManager.KEY_SIM_COUNTRY_ISO_OVERRIDE_STRING` → SIM 国家码覆写；
  - `CarrierConfigManager.KEY_CARRIER_NAME_OVERRIDE_BOOL` + `KEY_CARRIER_NAME_STRING` → 运营商名覆写；
- 传 `null` 即还原。覆写写在系统侧，**重启保持、双卡可分别设置、不用逐个应用 hook**。

**可借鉴点**：

- 预设的组织方式：一份国家清单（`CountryPresets`，28 个国家）+ 一份按地区分组的运营商清单
  （`PresetCarriers`，含中/英名）——本项目的预设表结构即受此启发，只是补上了 MCC+MNC、Locale、时区；
- 思路上的提醒：它改的是「系统对 SIM 信息的读取结果」。本项目用 hook 在应用侧达到同样效果，
  作用域只限谷歌应用，不影响全系统。

## 2. Xposed-Modules-Repo/com.tiktok.unlocker（GlobalKit）—— 本项目的仿照对象

**仓库性质**：这是 LSPosed 模块仓库的**上架元数据仓库**，不含源码（只有 README、SUMMARY、
CHANGELOG、metadata.json、THIRD_PARTY_NOTICES.md），APK 从其发布渠道分发。因此它的确切 hook
源码无从读到；功能面以其公开文档为准，实现结构以其第三方声明为准。

**功能面（README / SUMMARY）**：面向 TikTok 国际版，一键伪装——

- SIM 国家码、网络国家码；
- 运营商名称 / 编号（MCC+MNC）；
- 系统语言（Locale）；
- 系统时区；
- GPS 经纬度（本项目未做：谷歌应用的位置主要走网络定位，且任务范围未要求）。

**实现结构（THIRD_PARTY_NOTICES）**：

- 基于 **libxposed Modern API 102**（`io.github.libxposed:api` + `io.github.libxposed:service`），
  Kotlin + Jetpack Compose 设置界面；
- libxposed 102 的配置通道是 Service 提供的 RemotePreferences：设置进程写入、hook 进程经服务读取，
  这是 Modern API 下的「成熟做法」；
- CHANGELOG 显示：1.0.5 起「启动时自动刷新远程配置」，1.0.6「更换地区立即生效」。

**本项目的对应选择**：

- hook 的信号面与 GlobalKit 对齐（Telephony 国家/运营商 + Locale + TimeZone），并按谷歌应用的
  实际读取习惯额外覆盖了 `Resources.getConfiguration()` 的 locale 与 `gsm.*` 系统属性；
- 框架层选用等价的经典方案：**Xposed API 82 + XSharedPreferences**（LSPosed 完整支持，
  工具链简单、无需额外服务进程）。设置界面写 `SharedPreferences` 并放开文件读权限，
  hook 侧用 `XSharedPreferences` 读取；读不到配置时回退默认预设（美国），与 GlobalKit
  「选地区即生效」的交互一致（本项目需强停目标应用后生效，见 README 的已知限制）。

## 3. 两者对比小结

| | Nrfr | GlobalKit | 本项目 |
|---|---|---|---|
| 层级 | 系统运营商配置覆写 | 应用进程内 hook | 应用进程内 hook |
| 权限/框架 | Shizuku，无 Root | LSPosed / LSPatch | LSPosed |
| 作用范围 | 全系统、按 SIM | 作用域内应用 | 作用域内谷歌应用 |
| 信号 | SIM 国家码、运营商名 | 国家/运营商/Locale/时区/GPS | 国家/运营商/Locale/时区/Configuration/gsm 属性 |
| 配置 | 应用内选择，系统侧保存 | 应用内选择，远程配置 | 应用内选择，XSharedPreferences |

## 3. v1.1 界面改版记录（2026-11-21）

按用户真机反馈与 GlobalKit 截图对照改版：

- v1.0 的 ListView 单列表界面顶部状态行被裁切 → 改为全程序化卡片界面 + ScrollView，
  顶部状态卡、地区卡、运营商区、GPS 卡、伪装值面板、说明、设置入口纵向排列，不再裁切。
- 数据模型从「一个预设打包」拆为 国家 → 运营商 二级联动（照 GlobalKit：
  台湾→中华电信/台湾大哥大/远传；美国→T-Mobile/AT&T/Verizon 的卡片式单选），
  切国家自动重置运营商与 GPS 城市；国家扩到 14 个并加可搜索选择列表。
- 新增设置页：外观三档（跟随系统/浅/深）+ 主题色（橙默认，同 GlobalKit；蓝/绿/紫/红），
  代码配色实现，不依赖系统主题资源。
- 新增可选 GPS 伪装（默认关）：hook Location.getLatitude/getLongitude 与
  LocationManager.getLastKnownLocation，坐标为所选城市 + 按包名哈希的稳定小偏移。
